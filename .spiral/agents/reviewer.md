# Reviewing in lstk

Spiral's persona above covers the driver contract, the review procedure and the findings format. This file adds what is specific to lstk, LocalStack's Go CLI, where `CLAUDE.md` is the contract the diff is held to.

## What you read

- `CLAUDE.md`, and the checklist in `.claude/skills/review-pr/SKILL.md`. Read the file; don't invoke the skill, which takes a PR number and reads the PR with `gh`, which this machine doesn't have. Apply its checklist to `git diff origin/main...HEAD` instead.
- The implementer's commit bodies: round summaries, `## Deviations`, and which tests were not run on the worker.
- The branch's openspec change under `openspec/changes/<id>/`: the plan, read before the code.

Run nothing heavier than a single test: the gate already validated the openspec change, ran gitleaks over the commits, and ran lint, the unit and launcher tests, and the integration suite with Docker unreachable.

## What to check, every instance in one round

- **The openspec change matches the code.** The gate already validated it (`openspec validate --strict`, every task ticked, no existing openspec file touched). Check what it cannot: every behaviour the diff adds or changes is a requirement in the delta, and every scenario is pinned by a test; `design.md` records the decisions actually taken, including any the spec left open, and has no open question the change depends on; `proposal.md` cites the issue and names any in-flight change it relates to. A branch with an `openspec: none` line must really change no behaviour.
- **Test first, observable only.** A behaviour change or bug fix comes with an integration test in `test/integration/` that asserts what a user sees (exit code, output, files, requests a mock receives), never internals. A unit test alone is a gap when an integration test was practical.
- **Test hygiene.** `testEnvWithHome` instead of the real `$HOME`; `t.Parallel()` unless the test starts containers; fakes via `writeFakeTool`, never shell scripts; no `runtime.GOOS == "windows"` skip for convenience; mocks regenerated by `make mock-generate`, never hand-edited.
- **Docker-backed tests** that were not run here are written like their neighbours (`requireDocker(t)` before `env.Require(t, env.AuthToken)`), and everything that could be covered without Docker is.
- **Layering.** No business logic in `cmd/`; no `config.Get()` in domain packages; no Bubble Tea imports outside `internal/ui/`; no package-level mutable globals.
- **Output.** No direct stdout or stderr writes: user output goes through `output.Sink`, diagnostics through `log.Logger`. A new event type touches `events.go`, `plain_format.go` and the output tests together. Failures are an `ErrorEvent` plus `output.NewSilentError`.
- **Input.** Prompts use `output.Confirm`, `ActionChoice` or `Acknowledge`; non-interactive mode never waits on stdin.
- **Validation.** User-supplied values go through `internal/validate`, never an inline regexp.
- **CLI surface.** `emulator`, not `container`, in user-facing text; help text as unbroken paragraphs; no Cobra `Deprecated`.
- **Comments and docs.** Comments short and about the why; `CLAUDE.md` or doc comments updated when the change spans packages or alters a documented contract.
- **Release machinery** (`.github/workflows/`, `.goreleaser.yaml`, `scripts/`) and `.spiral/` untouched unless the spec names them.

## Judging deviations

- "Docker-backed test not run here" is expected, not a gap, when the test is written correctly and the rest is covered without Docker.
- A behaviour the spec asked for that `CLAUDE.md` forbids (a direct `fmt.Println`, a flag defined in a domain package): `CLAUDE.md` wins, and the implementer's deviation saying so is correct.
